# Node reference

Generated by `tools/generate_docs.py`; do not edit by hand.

40 node types in 8 categories.

Every node also carries parameters that are not listed below:

- **Extra flags** — appended verbatim to the command that node runs, so an option Comfy-gmx does not model is never a dead end. The box names that command, and in the editor it carries the command's own flag list with a one-line definition each, taken from its help output by `tools/harvest_flags.py`. A node with no single command to append to — one that copies a file or draws a picture — has no such box. On the run-parameters node the same box takes raw `key = value` mdp lines instead.
- **Conda env override** — run this one node inside a different environment than the one registered for its tool.

Every node also has a step-by-step panel, reached from the gear on its header or from its right-click menu. It is the same boxes with room around them: each explanation is on screen instead of in a tooltip, nothing is hidden behind a triangle, what is plugged into each input is listed, and the command that will run sits at the bottom and changes as the boxes do. Boxes marked below as having a fill-in-the-blanks form get a button there and on the node itself, which asks for that box's contents with dropdowns and numbers instead.

## Input / Output

### Load structure

`io.structure` · tool: `shell`

Brings a structure into the workflow, from this computer or from the Protein Data Bank. The first box says which.  From this computer: the file is copied into the run folder, so nothing downstream can touch your original. Large files are linked rather than copied, so pointing at a big trajectory costs no disk.  From the Protein Data Bank: give the four-character code -- 1AKI, 6VXX -- and it is downloaded. Needs an internet connection.  Before running anything, right-click it. 'What is in ...' lists the chains and whatever else the file holds, and 'What is missing ...' shows which residues the experiment never resolved -- usually the thing that decides your next step.

### Edit a text file

`util.edit_text` · tool: `python`

Makes small, exact changes to a text file -- a topology, a settings file, a structure, a mapping file -- by rules written in plain words, and says what each rule did.  This is the block for the little corrections that published files need: an #include that points at a file GROMACS no longer ships, an ion that is commented out, a residue name that is wrong on every line, a section a newer GROMACS insists on. Each rule is one line, such as  replace: OLD => NEW  or  uncomment lines starting with: NA.  A rule that finds nothing is an error, unless the file already looks the way the rule wants -- then it says so and carries on, so the same graph can be run twice. The file that comes out keeps the kind of the file that went in: a topology stays a topology, a structure a structure.

### Define box (editconf)

`gmx.editconf` · tool: `gmx` · extra flags go to `gmx editconf` · [docs](https://manual.gromacs.org/current/onlinehelp/gmx-editconf.html)

Puts the molecule in a box, which is what a simulation actually runs in.  The distance you set is the gap between the molecule and the wall. Too small and the molecule feels the copy of itself in the next box across the boundary, which is a common and quiet way to get wrong answers; 1.0 nm is the usual smallest and 1.2 the usual choice.  Right-click the node and choose "Pick the box by eye" to see the molecule drawn inside the box, what each shape costs in water, and how close the molecule comes to its own image -- rather than typing a number and hoping.

| Input | Type | Required |
|---|---|---|
| structure | `structure` | yes |

| Output | Type |
|---|---|
| conf | `structure` |

| Parameter | Type | Default | Notes |
|---|---|---|---|
| Box type | choice (cubic, triclinic, dodecahedron, octahedron) | `dodecahedron` | All four leave the same room around the molecule and differ only in how much of the corners is cut off -- which is water you would otherwise pay to simulate.  A rhombic dodecahedron holds about 29% less water than a cube, and a truncated octahedron about 23% less. For a roughly round molecule the dodecahedron is the usual choice.  Right-click and choose "Pick the box by eye" to see the difference in actual numbers of water molecules. |
| Solute-box distance (nm) | float | `1.2` | The gap between your molecule and the wall, so the closest it comes to the copy of itself in the next box is twice this.  It has to be more than the force field's cutoff -- usually 1.2 nm -- or the molecule interacts with its own image and the run is quietly wrong. 1.0 nm is the usual smallest, 1.2 the usual choice. Bigger is safer and costs water, and water is most of what a run spends its time on.  The box GROMACS builds is this gap at each end plus the distance between the two atoms of your molecule that are furthest apart -- not its width. A long thin molecule therefore needs a big box however thin it is.  'Pick it by eye' draws the molecule with the box around it, and says for each shape how many water molecules it would hold and how close your molecule comes to the copy of itself next door. |
| Centre in box (-c) | bool | `True` |  |
| Explicit box (nm) | str |  | Set this when the box size is dictated by a membrane patch, or when you are building a system in layers and every piece has to end up in the same unit cell. |
| Put the middle here (nm) | str |  | Where in the box the middle of the molecule goes, as three numbers measured from the corner. Blank puts it in the middle, which is what 'Centre in box' means.  This is how a system is built in layers. GROMACS measures every box from the corner at (0,0,0), so to keep a slab where it is while making the box twice as tall you ask for the same box and a middle a quarter of the way up -- and to put a second thing in the top half, three quarters of the way up. ### Ice crystal

`build.ice` · tool: `python` · [docs](https://doi.org/10.1063/1.1931662)

Builds a block of ice: ordinary hexagonal ice, the kind in a freezer, made of TIP4P/Ice water molecules -- a water model designed to melt at the right temperature, about 270 K where real ice melts at 273 K.  The block is made of small rectangular cells of 8 molecules each, 0.45 x 0.78 x 0.74 nm. The oxygens sit where the crystal puts them. The hydrogens are placed at random, but by the rules real ice keeps: every oxygen holds two hydrogens and points them at two of its four neighbours, and every pair of neighbours shares exactly one. The crystal has no overall electric dipole, as real ice has none.  Out come the crystal, a topology that says what a TIP4P/Ice molecule is, and an index file with one group, 'Oxygens': one atom per molecule, which is the clearest way to look at the crystal.

|---|---|
| ice | `structure` |
| topology | `topology` |
| index | `index` |

|---|---|---|---|
| Cells along x | int | `6` | 0.45 nm each. 6 cells make 2.7 nm. |
| Cells along y | int | `4` | 0.78 nm each. 4 cells make 3.1 nm. |
| Cells along z | int | `4` | 0.74 nm each, and the direction the hexagonal channels run in: look down z to see the honeycomb. 4 cells make 2.9 nm. |

### Count the ice

`analysis.ice_count` · tool: `gmx` · [docs](https://doi.org/10.1021/jp510289t)

Goes through a trajectory and counts, frame by frame, how many water molecules are still part of the ice. A falling line is ice melting; a flat one is ice that holds.  A molecule counts as ice when its four nearest neighbours sit exactly as they do in a crystal (the CHILL+ test, Nguyen and Molinero 2015). Molecules on the outside of a crystal never count, because they have no neighbours on the outside, so a small crystal starts well below its full number of molecules.

A rough look at a run: wire a trajectory and its tpr in and it plays the motion inside the node.  It is deliberately cheap, and cheap is the point -- it pulls a few dozen evenly spaced frames of one selection out with trjconv rather than trying to be a trajectory viewer. Enough to see whether the protein stayed folded, whether it left the box, whether the membrane held together. For anything you would measure, use the analysis nodes.  The frames it takes are written out as a multi-model PDB, so the same file opens in VMD or PyMOL if the rough look raises a question. That file is uncompressed text and it adds up -- 200 frames of a 13000-atom selection is 195 MB -- so take fewer frames of a smaller selection than you would for analysis.

| Input | Type | Required |
|---|---|---|
| trajectory | `traj` | yes |
| tpr | `tpr` | yes |
| index | `index` | no |

| Output | Type |
|---|---|
| frames | `structure` |

| Parameter | Type | Default | Notes |
|---|---|---|---|
| Which frames | choice (every Nth, about this many) | `every Nth` | 'every Nth' is one trjconv call and starts immediately. 'about this many' has to count the frames first, and counting means reading the whole trajectory -- half an hour for a 46 GB file on a network share. Worth it when you do not know how long the run is; not worth it twice. |
| Take every | int | `25` | Every Nth frame, counted in frames and not in time, so it costs nothing to work out. There is no good default for every run -- 25 is a few dozen pictures out of a thousand frames and forty out of a thousand-and-one -- so look at what it wrote and change it once. |
| How many frames | int | `30` | Only used by 'about this many'. Thirty is enough to see a motion; the browser thins it again above sixty. |
| Selection | str | `Protein` | Which part of the system to show: the name of a group, or several names with commas between them, such as 'Protein, Ion'. 'Protein' for a fold, 'System' to see everything -- which for a solvated run is mostly water. 'Fill this in with a form…' lists every group this system has, with how many atoms each holds, and lets you tick several. **Has a fill-in-the-blanks form** -- the button under the box asks for this in questions. |
| Periodic boundary | choice (mol, atom, whole, nojump, none) | `mol` | 'mol' keeps molecules in one piece, which is what makes a protein stop exploding across the box edge. |
| Centre the selection | bool | `True` | Puts the selection in the middle of the box, so it does not walk out of view over the run. |
| -b (ps) | float | `0.0` | advanced. |
| -e (ps) | float | `0.0` | advanced. |
| Stop above (MB) | int | `200` | advanced. A frame of a big selection is a lot of text: 200 frames of 13000 atoms is 195 MB of PDB, written into the run directory and kept. Above this the node takes fewer frames instead, and says so. 0 turns the limit off. |
| Output name | str | `frames.pdb` | advanced. |
